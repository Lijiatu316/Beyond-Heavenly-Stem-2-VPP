## 9.1.1 协同模式优化结论

### 论文指标

- ADMM 收敛次数
- 协同模式成本降幅
- 新能源消纳率提升

### 项目数据来源

| 论文指标 | 项目文件 | 具体位置 |
|---------|---------|---------|
| ADMM 迭代次数 | `02_算法核心模块/02_分布式协同调度/admm_distributed_opt.m` | 第 118-125 行：`primal_residual` 和 `dual_residual` 收敛判断。收敛时 `iter` 即为迭代次数 |
| 每步迭代记录 | `run_mode_cooperate.m` | 第 196 行：`hist.admm_iter(t) = admm_info.iterations` |
| CSV 输出 | `cooperate_timeseries.csv` | 列 `ADMM_Residual` — 每步的原始残差值 |
| 前端图表 | `dashboard_cooperate.html` | ADMM 收敛曲线图：残差从 ~0.65 指数衰减至 ~0.001 |
| 成本对比 | `dashboard_cooperate.html` | 模式性能对比面板 — 孤岛 vs 协同的调度总成本 |
| 消纳率 | `04_辅助工具/03_告警与指标计算/calculate_eco_index.m` | `renewable_rate` 字段 |

### 写结论时引用

```text
ADMM 算法在 [平均迭代次数] 次内收敛至容差 0.005 以下。
相较于孤岛模式，协同调度使总成本降低约 [X]%，新能源消纳率提升 [X] 个百分点。
VPP 间功率互济总量达 [X] kWh，验证了分布式协同在经济性和可再生能源利用方面的优势。
```

### 获取数据

1. 运行 `run_mode_cooperate()` 生成 `cooperate_timeseries.csv`
2. 打开 `dashboard_cooperate.html` 查看 ADMM 收敛曲线和模式对比面板
3. 取 `hist.admm_iter` 的均值作为平均迭代次数

## 9.1.2 孤岛模式控制结论

### 论文指标

- 频率偏差
- 恢复时间
- 电压偏差

### 项目数据来源

| 论文指标 | 项目文件 | 具体位置 |
|---------|---------|---------|
| 频率偏差 (Δf) | `02_算法核心模块/01_离线自治调度/freq_volt_pi_control.m` | 第 28-35 行：Droop 控制 `delta_f = -R × f_nom × delta_P / P_base` |
| PI 二次调频 | 同上 | 第 38-52 行：积分控制 `P_corr = Kp × Δf + Ki × ∫Δf dt` |
| UFLS 保护 | 同上 | 第 60-72 行：连续 10 步低于 49.5Hz 触发 20% 切负荷 |
| 频率时序 | `island_timeseries.csv` | 列 `VPP1_Freq_Hz` ~ `VPP3_Freq_Hz` |
| 前端展示 | `dashboard.html` | 系统频率趋势图：49.5-50.5Hz 安全区间（绿色带）+ 阈值线（红色虚线） |
| 阶跃响应测试 | `04_辅助工具/04_测试小脚本/test_island_freq.m` | 80kW 负荷突增 → 测量频率恢复时间 |
| 电压偏差 | `freq_volt_pi_control.m` | 第 75-90 行：Q-V 调压，`hist.volt` 记录每步电压标幺值 |

### 写结论时引用

```text
PI 控制器将系统频率维持在 50 ± 0.5 Hz 范围内，频率合格率达到 [X]%。
80kW 负荷阶跃时，频率最大偏差为 [X] Hz，恢复时间约 [X] 秒。
Q-V 调压使电压偏差控制在 ±[X] p.u. 以内。
```

### 获取数据

1. 运行 `run_mode_island()` 生成 `island_timeseries.csv`
2. 打开 `dashboard.html` 查看频率趋势图
3. 运行 `test_island_freq` 获取阶跃响应数据
4. 取 `hist.freq` 中超出 49.5-50.5 的步数 → `freq_qualified_rate = 合格步数 / 总步数`

## 9.1.3 双模式切换结论

### 论文指标

- 切换时间
- 暂态波动
- 平滑可靠性

### 项目数据来源

| 论文指标 | 项目文件 | 具体位置 |
|---------|---------|---------|
| 通信质量检测 | `03_系统建模与设备/04_通信网络仿真/comm_delay_sim.m` | 计算延迟、丢包、质量矩阵 |
| 故障注入 | `03_系统建模与设备/04_通信网络仿真/comm_fault_trigger.m` | 按时间表注入通信故障 |
| 模式判定 | `02_算法核心模块/mode_judge_comm.m` | 任一链路 delay > 0.1s 或 loss > 0.3 或 avg quality < 0.5 → ISLAND |
| 模式记录 | `hist.mode` | 每步的模式标签（1=COOPERATE, 2=ISLAND） |
| 约束过渡 | `02_算法核心模块/03_统一约束处理/power_limit_handler.m` | 七道约束检查，确保切换时功率不突变 |
| PI 连续性 | `freq_volt_pi_control.m` | PI 控制器在模式切换时不重置，保持平滑过渡 |
| 首页展示 | `index.html` | Weak Signal Resilience 五阶段叙事：正常→降级→中断→自治→恢复 |

### 写结论时引用

```text
通信中断时系统在 [X] ms 内完成从协同到孤岛的切换，
切换过程中功率波动不超过额定容量的 [X]%。
通信恢复后系统在 [X] 个仿真步内重新建立 ADMM 共识。
整个切换过程平滑、可靠，未出现供电中断。
```

### 获取数据

1. 运行 `run_mode_cooperate()`（需包含通信故障注入）
2. 分析 `hist.mode` 的跳变时间点
3. 比较切换前后各 5 步的功率、频率和电压变化

## 9.1.4 预测模型结论

### 论文指标

- 风电 R² / MAE
- 光伏预测精度
- 潮汐模型

### 项目数据来源

| 论文指标 | 项目文件 | 具体位置 |
|---------|---------|---------|
| 风电 LightGBM | `预测汇总/风电/最终模型.py` | `wind_power_lgbm_model.pkl` — 输入：风速/风向/温度/气压/历史出力 |
| 风电测试数据 | `预测汇总/matlab_input/wind_power_24h.csv` | 240 行参考预测值 |
| 光伏物理模型 | `预测汇总/光伏/pv_model_engine.py` | 辐照度 × 面板面积 × 效率系数 × 温度修正 |
| 光伏参数 | `预测汇总/matlab_input/pv_params.csv` | 11 个物理参数，来自 `pv_power_model.bin` |
| 潮汐参数 | `预测汇总/潮汐/电站参数.xlsx` | 江厦潮汐电站：库容、水头范围、机组配置 |
| 潮汐模型 | `03_系统建模与设备/01_分布式电源模型/tidal_model.m` | 单库单向 ebb generation |
| MATLAB 对接 | `预测汇总/export_for_matlab.py` | 将 Python 预测输出整合为 `scenario_24h.csv` |
| 场景输入 | `预测汇总/matlab_input/scenario_24h.csv` | 240 行：辐照度 / 温度 / 风速 / 负荷 / 潮高 |

### 写结论时引用

```text
风电 LightGBM 模型在测试集上 R² 达到 [X]，MAE 为 [X] kW。
光伏物理模型基于真实组件参数，预测功率与实际出力吻合良好。
潮汐模型采用江厦潮汐电站实测参数，
单库单向发电模型准确反映了潮汐周期性出力特征。
```

### 获取数据

1. 在 Python 环境运行 `最终模型.py`，使用 sklearn 的 `r2_score` 和 `mean_absolute_error`
2. 光伏模型直接由面板参数和气象数据计算，通过对比 `pv_power_24h.csv` 与仿真实际值
3. 潮汐模型参数已在 `电站参数.xlsx` 中
